# Ablation E1 - single agent vs parallel specialists (2026-10-15)

**T7.3, experiment E1, on the v2 catalog.** Registered in [`PREREGISTRATION-T7.3.md`](PREREGISTRATION-T7.3.md) before the build and before any run (the switch: Addendum 1; the queue and the nights: Addendum 3). The switch was proven to take effect in the switch trial ([`PREREGISTRATION-trial-v2.md`](PREREGISTRATION-trial-v2.md), Addendum 8).

**What varies.** F's pipeline (triage, planner, four parallel specialists, synthesizer, proposer, scribe) against B1: one agent with the same five tools and no fan-out (`--baseline b1`). **B1 differs in more than the fan-out**: it has no retrieval, no proposer and no scribe, and it is never gated by triage. The result is about all of those together, as the registration says.

## Reading it

**This is the one experiment whose difference clears the MDE, and it goes against the
multi-agent design.** One agent with the same tools named the fault class on more of the ten than
the full pipeline did, and the interval excludes zero. The culprit service moves the same way,
past the MDE with its interval reaching zero. Set the gate aside (F's one gated scenario), as the
registration asks, and fault class still clears the MDE.

**It is not a one-off.** The headline run measured the same comparison on 27 dev scenarios,
independently, and found B1 ahead on fault class there too, with an interval that excludes zero
([`HEADLINE-2026-10-11-v2.md`](HEADLINE-2026-10-11-v2.md) §2). Two separate batches, different
nights, the same sign. On holdout the two tied (§1 there), on nine scenarios.

**Where the difference sits**, scenario by scenario: B1 got right four scenarios F did not -
the bad config F abstained on, the disk fill F called a partition, the dependency latency triage
gated, and the valkey latency F called a bad config. Both missed the product-catalog freeze. F got
nothing right that B1 missed.

**The registered prediction was wrong twice.** It said the accuracy difference would sit inside
the MDE (it did not) and that B1 would cost 30-70 % less (it cost about the same). B1 *is* much
faster to report: it skips the planner, the fan-out and the synthesis round.

**What it means for the architecture**, stated as narrowly as the record allows: on this world
and this catalog, the fan-out to four specialists, the planner and the synthesis step do not buy
accuracy over one capable agent holding all the tools; they cost latency and, through the gate,
a scenario. The confound runs both ways - B1 also lacks retrieval, whose worth E5 could not
measure at this size, and the gate, which cost F one scenario - and this batch cannot separate the parts.
A follow-up that could: F with triage's gate off, and B1 with retrieval on.

## What this does not establish

- **A size.** Ten dev scenarios at R = 1 resolve nothing smaller than the MDE above, and the
  interval beside every difference says how little is pinned down. The plan asked for the full
  catalog at R = 5; the owner's scale (12 scenarios, then 11, then 10 after one was removed) is
  registered in `docs/DEVIATIONS.md`.
- **Anything about holdout.** Dev scenarios only, by ADR-0008: an ablation's result is what tuning
  reads.
- **A control without noise.** F is one run per scenario. The A/A table in `docs/ABLATIONS.md`
  shows the same configuration changing its mark on half the scenarios between two runs nine days
  apart, so any single scenario's difference here can be noise; only the paired difference over
  all ten is read.
- **Anything about another world.** OTel Demo 2.2.0 on the Mac, at `cap:91279a09`; nothing here is
  about SREGym.
