### The freeze, verified after the run

Five of the six items are byte-identical to the manifest: `runtime_version`, `prompts.sha256`,
`corpus`, `model_map`, `budget`, `judge`. The sixth, `tool_layer.git_sha`, moved by **exactly one
commit — the freeze commit itself**, and `git diff 5e54c85..HEAD -- src/faultline/` is empty.

That is a self-reference flaw in the manifest rather than a freeze break: the sha is computed
before the manifest is written, and writing then committing it necessarily changes the sha. It is
**recorded, not fixed** — fixing anything during a holdout run is exactly what the freeze
forbids. A follow-up should record the tool layer as "the commit this manifest is committed as",
or verify no frozen surface changed rather than that no commit happened.

## What surprised the run

**Coverage, not accuracy, is where holdout differs from dev.** 1/3 against 4/7. Everything the
agent asserted on holdout was right; it asserted once.

**On holdout the abstentions line up exactly with budget exhaustion, and on dev they did not.**
Both holdout abstentions exhausted the same bound — `changes tool calls: 4 of 4` — and the run
that answered did not. On dev, one abstention was exhausted, two were not, and one exhausted run
answered. **With n=3, this data cannot separate "the taxonomy instruction causes abstention" from
"the planner spends its `changes` budget and leaves the synthesizer nothing to classify from".**
The dev data says they are separable there; the holdout data says they coincide here. That is a
question for a run with a larger per-specialist bound, and it is not answered by anything in this
repository today.
