# Checkout PlaceOrder failures traced to an unreachable cart endpoint

## What was visible, and the first three dead ends

The page named checkout, frontend, frontend-proxy and load-generator at once, severity critical, thirteen services in the blast radius. That breadth suggested an edge or proxy problem; it was an artifact of one error status propagating up a single call tree. The symptom was PlaceOrder failing intermittently, with successful checkouts interleaved throughout.

Three opening moves produced nothing usable. Checkout's change log was empty across a window starting at onset and running roughly twenty-four hours forward — no change to blame, no remediation either — but it was scoped to the seed service only, zero hops, so it says nothing about cart or any other neighbour. Checkout's error-ratio metric showed a mean about 1.43x baseline, but with huge dispersion, returns to zero inside the incident window, and an identical maximum in both windows: no step change, no new severity ceiling. It was aggregated by service name alone, so it could never have attributed the failure to a dependency anyway. Checkout's logs returned not zero error lines but zero lines of any kind for the full thirty-two minutes, untruncated — anomalous for a serving path, most likely a selector mismatch or an ingestion gap, and emphatically not evidence of clean operation.

## The turn: traces, then frontend logs

Traces settled it. In every failing trace the deepest erroring span is checkout's own client call to CartService/GetCart, marked error with gRPC UNAVAILABLE and a name-resolver result of zero addresses; the parent PlaceOrder span wraps the same condition. Those spans finish in roughly zero to a tenth of a millisecond, which rules out timeouts, queueing and saturation — the call never left the client. No cart-side span appears in any failing trace. Every other checkout edge (currency, product-catalog, shipping, payment, email, cart EmptyCart, the orders publish) is clean at normal latency, SQL spans complete in milliseconds, and frontend, frontend-proxy and load-generator merely inherit the error downward. Successful traces in the same window show GetCart completing normally with cart serving HGET, so cart was intermittently reachable rather than continuously gone.

Frontend's logs corroborate independently: repeated code-14 transport failures against a single container-range address on port 7070, last-error timestamp pinned at 23:33:30.810 and still failing at the window edge, plus one line naming a cart RPC on the checkout path whose resolver returned no endpoints. The mode shifted from connection-refused around 23:08 to host-unreachable later, same address and port. Note the result was truncated to the oldest eight and newest thirty-two lines, so nothing between roughly 23:08 and 23:34:52 was actually returned.

## The tempting wrong answer, conclusion, and what is still open

Frontend's change log looked like the answer: four edits to a CART_ADDR variable pointing at cart on a non-default port. It does not hold. They form two complete set-then-revert pairs by the same platform-automation actor, ending with the variable unset, all landing 21 to 22 hours before onset, with nothing recorded in the ~21 hours before. No deploy, no flag flip, no human operator, no override in effect at onset.

Conclusion: the failure is at the network/discovery layer between callers and cart — zero resolvable addresses plus host-unreachable to a previously working container IP — not inside checkout and not cart erroring or slowing. Fix class: reconnect. Confidence medium.

Still open: no specialist was ever sent to cart, so its logs, metrics, change history and container/network state are entirely unexamined and the severance is inferred only from callers' symptoms. The same endpoint was already refusing connections ~25 minutes before the stated onset — same failure in an earlier phase, or a separate precursor, is unsettled. And why successful GetCart calls interleave with failures (intermittent resolvability versus partial endpoint withdrawal) is unexplained.
