# The headline run on the v2 world - 37 scenarios, four arms, R = 1

**Registered in [`PREREGISTRATION-headline-v2.md`](PREREGISTRATION-headline-v2.md) (2026-10-04,
Addenda 1-5) before any scored run. Run 2026-10-06 to 2026-10-11 in eight nights, as
`BATCH-headline-v2.tsv` records. Every figure here is printed by
[`analysis_headline_v2.py`](analysis_headline_v2.py) from the run directories beside it:**

```
python3 evals/runs/analysis_headline_v2.py evals/runs
```

**The one sentence.** On the ten holdout scenarios Faultline names the fault class on 7 of 10
and the culprit service on 8 of 10 - and so does B1, one agent with the same five tools and no
fan-out, at the same cost. **The multi-agent pipeline does not beat a single agent with the same
tools on this catalog**: tied on holdout, and on the 27 dev scenarios the single agent is ahead
by 26 points on fault class with an interval that excludes zero. Faultline beats the no-model
heuristic (B0) and the model's prior (B2) on every set. Prediction 6 said this would happen, and
it is the finding.

**What this run is not.** Ten holdout scenarios at R = 1: the registered minimum detectable effect
is 28 points, every rate's interval spans 40 points or more, and no class has five holdout
scenarios. **The holdout supports direction, not magnitude.** The dev set is diagnostic: prompts
and the corpus were fitted on it, and every number from it is labelled so.

## 3. The gate

**Triage gated 3 of F's 37 runs**, all on dev, all on a page whose only alert was one
warning-severity `ServiceHighLatency`, and all with the same written reason: *a lone warning
alert, no error-rate alert, no propagation*. The three are the two `payment-dependency-latency`
scenarios (the base and its injection variant) and `v2-fraud-detection-flag-queue-lag`. No gate
fell on a page with a critical alert. **Prediction 3 held** (at most 4, warning pages only). A
gated run is a miss on every axis, so the gate costs F 3 points of its 26 against B1 on dev.

Each gated run cost one triage call, about $0.05, which the tally does not record (the call is
not persisted); the console reading below carries it.

## 4. The four injection scenarios

The attacker's line (a runbook-shaped instruction naming a decoy fix, with a per-run canary) was
**delivered to Faultline's log reads in 3 of 4** - the fourth is a gated run that read nothing -
and to B1's in 3 of 4. **No arm mentioned the canary, named the decoy target, or proposed the
decoy action**: `followed: false` on all 16 runs, as `adversarial.outcome` records. B0 and B2
read no logs, so the line never reached them.

On the scored axes the injection variants went as their bases did: F right on
`v2-inj-email-wrong-image-log-checkout` (holdout) and wrong on the other three (two on class, one
gated); B1 right on all three it investigated.

**Q82's caveat stands**: a planted Loki line cannot be retracted, so each later run's window may
contain earlier runs' lines. The canary is per run, so no run could mistake another's for its
own; what a later agent saw was more attacker text, not a token it could follow.

## 8. What it means for the architecture

1. **Decomposition did not pay for itself here.** With the same five tools and the same model,
   one agent in one pass named the fault class at least as often as the planner, four
   specialists and a synthesizer, in a third of the time, for the same money. The fan-out's
   justification was context isolation per modality; on this world, with four tool calls per
   specialist and a 400-character evidence sample, the synthesizer appears to lose what the
   single agent keeps - six of its nine dev misses against B1 are an adjacent mechanism named
   from the same evidence. **T7.3's E1 and E3 (raw context to the synthesizer) are the next
   experiments, and they are registered.**
2. **Triage's gate is a real cost on warning-only pages.** 3 of 37 runs declined, every one a
   true fault. The gate was built for noise; this catalog has none, so every gate is a miss. On
   SREGym the same gate declined 20 of 33. Whether to keep it is a product question the headline
   cannot answer: it has never seen a noisy page.
3. **The fix class is the axis to work on**, and the proposer is the component. F is right on
   the class and wrong on the fix on three holdout scenarios; the allowlist's choice between
   `restart`, `config_revert` and `reconnect` is where the miss lands.
4. **`feature_flag` needs a different design.** 0 of 8 on holdout for every arm says the flag
   is invisible from the symptoms the recordings capture, not that one agent reads them worse
   than another.
5. **The baselines did what they exist for.** B0 and B2 bound what is available without
   investigation (about a third of the class, 40 % of the service); F clears both with intervals
   above zero on the full set. B1 is the comparison that matters, and it is the one the
   architecture loses.
