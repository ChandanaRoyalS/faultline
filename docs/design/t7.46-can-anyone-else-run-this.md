# T7.46 — can anyone else run this?

An audit of the documented path as written. **Honest conclusion: a stranger can run the demo and
read the results; a stranger cannot reproduce a figure, and the front door does not tell them how.**

## What was fixed, because it was cheap and clearly wrong

| was | now | why it mattered |
|---|---|---|
| *"give it ~2 minutes to settle"* | **~5 minutes**, with the reason | the baseline gate refuses containers younger than **300s**. A stranger following README exactly gets a refusal on their first `make demo` and has no way to know it is expected |
| *"Twelve scenarios, ten runnable and two that could not fire"* | **17 authored, 13 valid, 4 blocked** | stale on all three numbers |
| *"n is 3 on holdout and 7 per dev sweep"* | **7–8 per dev sweep**, 0–3 per class, two scenarios at n = 2 | contradicted README's own banner, which reports *"8 of 8 scenarios scored"* |
| no prerequisites at all | **Docker, uv, Python 3.12, git, key** | `make world-up` clones a repo and starts ~20 containers; a machine without Docker fails opaquely |
| platform unstated | **a platform note** | see below — this is a reproduction claim, not a convenience |

**Verified as correct and left alone:** the key path `~/.faultline-anthropic-key` (matches
`demo.KEY_PATH`), `make world-up` / `make demo` / `make check`, all four `faultline-inject`
subcommands including `stop --all`, and `docs/demo/`'s transcript and narrative.

## Structural gaps — written down, not fixed on my own judgement

**1. README documents the demo and the injector, and never the scored harness.** `faultline-eval`,
the recorder, `faultline-judge`, `faultline-render` and `faultline-seed` appear **nowhere in
README**. Every figure in the results section was produced by a command the front door does not
name.

**Consequence, and it is the sharpest one:** since T7.33 a scored run **refuses** unless it declares
`--single-run` or `--runs-remaining N`. That requirement is documented **only in `docs/PLAN.md`**. A
stranger who finds `faultline-eval` and runs it gets

```
REFUSED: say whether this is one run or part of a sweep.
```

and nothing they have read explains it. **The refusal message is good; its absence from the
documentation is the defect.**

**2. `evals/scenarios/ARTIFACTS.md` is not linked from README.** T7.33 put the recorder's contract
there — that a dirty baseline makes it **wait up to 300s rather than refuse**, which step waits and
for how long, and **not to queue a retry against that message**. That contract exists precisely
because misreading it produced T7.36's near-miss. **It is one directory deep and unreachable from
the front door**, so the reader most likely to repeat that mistake is the one who cannot find it.

**3. World hazards a stranger will hit, with no forewarning in reader-facing docs.**

| hazard | documented where | reachable from README? |
|---|---|---|
| **kafka headroom refusal** | nowhere reader-facing | **no** |
| **restarting kafka strands `accountingservice`** | `CATALOG.md` | yes, but as a scenario note |
| **the checkout stall is a known pathology with a prescribed remedy (ADR-0025)** | `ARTIFACTS.md` | **no** |

The gate messages themselves are good — the headroom refusal names the container, the threshold,
the derivation and the remedy. **But a stranger meets them as failures before they meet them as
documentation**, and a benchmark whose first three interactions are unexplained refusals reads as
broken.

**4. `make eval` is named in gate G4 and is a stub.** It echoes *"eval harness arrives in Phase 4"*.
G4 is marked ⬜ so the table is honest, but the command in the condition does not do the thing.

## What reproduction actually means here, and whether the documents say it

**Bit-for-bit reproduction is impossible and the documents should not imply otherwise**: the world
drifts, the model is nondeterministic, and T4.10 measured a 2.6× breadth spread on a single
scenario.

**What a reader needs instead is to know when their run is comparable to ours.** Four things
determine it, and the documents cover them unevenly:

| | stated? |
|---|---|
| **which world a figure describes** | **yes** — README's banner names `compose_digest f5bd108f…` and marks older figures as superseded (T7.29) |
| **that the figures are label-level** | **partly** — the figures are named as coverage, fault class, class of fix, judged `same_mechanism`, which is accurate. **But nothing says the benchmark does not assess *warrant*** (T7.44), and README's opening — *"investigate the way a good on-call engineer would"* — invites the stronger reading |
| **what makes a run incomparable** | **partly** — the world boundary is stated; **the pipeline stamp is not explained as a comparability boundary**, and `prompts:1b0e7cbb4c47` appears in figures without saying that a different stamp makes them a different experiment |
| **platform** | **was missing; added by this task.** Every figure was produced under arm64 Rosetta emulation, which T7.30 measured as changing container memory behaviour. **A run on x86 is a different world** |

**So the honest answer to "what does a reader need to trust a figure": they need the world digest,
the pipeline stamp, the platform, and the knowledge that the numbers are label-level. README carries
one of those four in full, one partly, and was missing two.**

## What could not be verified without a from-scratch run

**Not attempted, deliberately** — tearing down and rebuilding costs hours and risks the world the
recorded bundles describe.

| step | why it needs a real run | cost to verify |
|---|---|---|
| `make world-up` from a clean clone | clones the demo at a pinned tag and pulls ~20 images; network, disk and registry availability are all untested here | ~20–30 min, plus a full world teardown first |
| the world reaching a passable baseline | depends on image pulls, host resources and the 300s settle | included above |
| `make demo` end to end | real model calls; **needs credit, and the account has none** | ~15 min + ~$0.40–0.70 |
| `uv sync` on a machine without the lockfile's cache | dependency resolution is untested from cold | ~5 min |
| the whole path on **x86** | never attempted; ADR-0005's emulation premises do not hold there | unknown, and it is a different world by construction |

**Total to verify the documented path honestly: a teardown, ~1 hour of world time, and ~$0.50 —
on a machine that is not this one.** That last clause is the real cost: verifying a stranger's
experience requires not being the operator who already knows.

## Conclusion

**The path works for the demo and fails for reproduction.** A stranger can clone, bring the world
up, run the demo, and read every figure with its provenance banner. They cannot produce a figure of
their own, because the command that produces figures is not documented, its mandatory flags are
recorded only in the execution plan, and the operational contract for the recorder sits in a file
the front door does not link.

**That is a real result about an open benchmark, not a documentation chore.** The claim on the first
line — *"an open, benchmarked incident-investigation agent system"* — is true of the artifacts and
not yet true of the path to producing them.

**What it would take** is one section documenting the scored harness: the invocation, the mandatory
intent flag, what each exit code means, the three world hazards and their remedies, and a link to
ARTIFACTS.md. **It is not written here because writing it is a structural change to the front door
and this task's brief was to find the gap, not to restructure on my own judgement.**

## Addendum (T7.47): the gaps are closed in documentation, not in verification

**All four structural gaps above are now closed** — README carries a "Scoring a scenario" section
with the mandatory `INTENT` flag and the exit codes; `evals/scenarios/ARTIFACTS.md` is linked from
it as *"the rehearsal contract"* rather than by filename; the three world hazards have a page at
[`docs/TROUBLESHOOTING.md`](../TROUBLESHOOTING.md) reachable from both the demo block and the
scored-run section; and `make eval` is a real target that refuses without `SCENARIO` and `INTENT`
instead of echoing that the harness has not arrived.

> **None of this has been tested by a cold run.** The claim is **"the path is now documented"**, not
> **"the path now works"**. Everything in §"What could not be verified" still stands: a from-scratch
> `make world-up`, the world reaching a passable baseline, `make demo` end to end, and `uv sync`
> from cold remain unverified, at the same cost — a teardown, ~1 hour of world time, ~$0.50, **on a
> machine that is not this one.**

**What closing them does change** is that a stranger who hits a refusal now has somewhere to land,
and a stranger looking for the command behind the figures now finds it. **What it does not change**
is whether the first command works on their machine, which nobody has checked.
