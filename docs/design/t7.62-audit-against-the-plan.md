# T7.62 — audit against the proposal and the execution plan

**The audit could not be performed as specified, and the reason is the first finding.**

---

## 0. Neither source document is in this repository

The task names two sources — the **Faultline Project Proposal (REV 8, 2026-08-21)** and the
**Faultline Execution Plan (REV 9, 8 phases / 58 tasks / 8 gates)** — and asks for each task's
deliverable column and each gate's exit condition to be **quoted**. **Neither document is in the
tree.** `find` over the repository returns no proposal and no execution plan; nothing in any
markdown file cites "REV 8", "REV 9", "Execution Plan" or "Project Proposal".

**`docs/PLAN.md` is not the plan, and says so in its own first line:**

> **This file is not the plan.** The execution plan lives outside this repository. Every entry
> below was reconstructed by collecting task references from ADRs, scenario files, code comments
> and tests, and paraphrasing what those citations say the task will do. … Treat this as an index
> of what the codebase believes, not as authority.

**So auditing the repo against `docs/PLAN.md` would be auditing the repo against a document
derived from the repo.** Every "requirement" it states was harvested from the tree it is being used
to check, so the exercise cannot fail and its passing means nothing. That is the same defect this
project has found five times — a claim about a thing checked against a document that asserts things
about the thing (T7.34, restated at T7.57) — and running it here would be the sixth.

**Two things were therefore not done, deliberately.** No deliverable column is quoted, because
quoting one would mean inventing it. No task is marked *exists / partially exists / does not exist*
against the plan's wording, because the wording is unavailable and grading against a paraphrase of
a paraphrase would produce a table that looks like an audit and is not one.

**What was done instead:** every question in the brief that can be settled from the repository
alone was settled from the repository, and the answers are below. Where the brief names a specific
artefact, its **existence** is checkable without the plan even though the exact requirement is not.

*(Read on `main` at `da15eb7` = T7.59. T7.60's restructure of `RESULTS.md` is open as PR #110 and
not merged; nothing below depends on it.)*

## 1. The eight gates — none is recorded, and one has evidence

**`grep` for "Gate 1"…"Gate 8" across every markdown file in the repository returns four hits, and
none of them is a gate declaration:** CLAUDE.md's working rule *"from Gate 2 onward, no
prompt/context/architecture change lands without an eval comparison"*, two ADR asides referring to
"Gate 1's evidence", and the Gate 1 evidence README itself.

- **`docs/PLAN.md` contains the string "Gate" zero times.** The reconstruction found no gate
  citation anywhere in the tree to harvest.
- **Only Gate 1 has evidence**: `docs/evidence/gate-1/` — a README and three screenshots, dated
  2026-08-23.
- **Gates 2 through 8 have no evidence directory, no exit condition on record, and no declaration
  that they passed.**

**So the most important thing this audit could have found — a gate declared passed without its
condition holding — has no instance, because no gate has ever been declared at all.** That is not
better. CLAUDE.md's rule 4 reads *"Gates are hard — a task is done when its gate condition passes
from a clean clone"*, and **that rule is enforced by nothing and tracked nowhere.** It is the
largest single instance of this arc's recurring defect: a rule stated in prose, believed because it
is written down, with no mechanism and no record behind it.

**The two gates the brief flags, checked directly:**

**Gate 4 — *"`make eval` scores all ten scenarios unattended"* (as quoted in the brief).**
**The condition does not hold.** `make eval` takes `SCENARIO=<id>` and scores **exactly one
scenario per invocation**; it was a stub until T7.47 implemented it, and what T7.47 implemented is
a single-scenario wrapper. There is no all-scenarios driver in `src/evalharness/`. And *unattended*
fails on a second ground measured this session: **T7.58 ran six invocations back to back and three
were refused inside four seconds**, because `faultline-eval` does not wait for the world to settle
between runs — it refuses. Every multi-scenario sweep in this repository was driven by an ad-hoc
script written for that sweep.

**Gate 5 — *"the demo runs from a clean clone"*.** **Never tested as written.** T7.48 tore the
world down and rebuilt it, and stated the limit in the same breath: the teardown **reused local
images**, so it shows a *rebuild* is identical and not that a cold clone-and-pull is. README still
records that the demo end to end **remains unverified**. **Nobody has run this from a clean clone.**

**And `contract not written` appears 33 times in the reconstruction.** A third of the index is work
the repository performs with no plan statement behind it.

## 4. What the plan asked for that does not exist

**Phase 6 is essentially unbuilt and Phase 7's two priority tasks are untouched.** Of the plan's
Phase 6, the reconstruction found citations for only **T6.4** and **T6.8** — the retrieval corpus at
≥50 documents, which stands at **7**, and the security pass whose *core thesis* is prompt injection
via log lines, which has **no eval scenarios and has never been attacked**. **T6.5 leaves no trace
in the tree at all.** From Phase 4, the **B0/B1/B2 baseline suite the brief calls mandatory in every
headline table does not exist**, nor does the **Gate 4 A/A check**, nor **repeat tiers, an MDE table
or a single confidence interval** — against a closing rule that no number leaves without one. From
Phase 7, **T7.0 and T7.2 were never built**, and **T7.1's catalog growth is explicitly still owed.**
**And seven of the eight gates have no exit condition recorded anywhere**, so the plan's own
completion criteria are absent from the repository they were meant to govern.

## 5. What exists that the plan did not ask for

**Roughly fifty tasks of measurement infrastructure, self-correction and record integrity, none of
which the plan contains.** T7.6–T7.59 are IDs the plan does not have, and their subject matter is
consistent: world digests and re-records (T7.1's queue, T7.28, T7.48), a baseline gate that projects
kafka's memory forward (T7.31–T7.33), a world lock (T7.37), a freeze path wired into every run
(T7.54, T7.55), a judge run across the corpus (T7.52), reachability as a recorded field (T7.4, T7.5),
narrative capability stamping (T7.7, T7.8), a deferral register (T7.45), a troubleshooting guide and
a no-commit-on-main hook (T7.47), and five separate audits of the project's own claims. **Almost all
of it is defensible on its merits and almost none of it was asked for.** It is what a project builds
when it keeps discovering that its own record is unreliable — and the reconstruction's `contract not
written` marker, appearing 33 times, is the repository's own admission of exactly that.

## 6. Does the work since T7.30 serve the plan's stated priorities?

**No, and not marginally.** The brief states that if time compresses, **T7.2 and T7.5 outrank
everything else in the phase.** Since T7.30 the repository has completed **thirty tasks**, and
**neither of those two is among them** — T7.2 remains unbuilt, and the plan's T7.5 cannot even be
located because its ID is occupied. What those thirty tasks did instead: eight on world stability
and the memory gate, six on scenario authoring and the catalog, five on record integrity and audits,
four on the holdout protocol, and the remainder on freeze, locking, judging and queue hygiene.
**Every one is defensible in isolation and the sequence is coherent** — each task answered a defect
the previous one exposed. **But taken together they are a project auditing and repairing its own
measurement apparatus, not a project executing a plan**, and the two tasks the plan names as
outranking everything were never started. **The honest summary is that the last thirty tasks
optimised the trustworthiness of a small number of figures rather than the coverage the plan asked
for**, and that trade was never registered as a decision — it happened.

## 7. What would let this audit be completed as specified

**Put the two source documents in the repository, or supply them.** Then: quote each of the 58
deliverable columns and grade against them; quote each of the 8 exit conditions and check each
against evidence; and resolve every `contract not written` marker — 33 of them — either by finding
the plan statement or by recording that the repo invented the task. **None of that is possible from
inside the tree**, and producing it from `docs/PLAN.md` would be producing a document that grades
the repository against itself.
