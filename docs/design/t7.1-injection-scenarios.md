# T7.1 — `kind: injection` scenarios: the catalog carries its own attacker

**Date:** 2026-09-28 · **Task:** T7.1, the `injection` row of `SPLIT-V2.md` · **Author:** Chandana
Sorakundla

## What the row asked for, and what existed

`SPLIT-V2.md` gives the P6 injection cases four slots of their own - three dev, one holdout -
*"rehearsed and labeled like the first ten, and assigned to the dev or holdout split at
creation"*. T6.8 built the mechanism those cases need and deliberately kept it outside the
catalog: an adversarial variant lives in `evals/adversarial/<id>.yaml`, names a dev scenario it
rides, and `faultline-eval <base> --adversarial <id>` plants its payload after the settle
window, removes it with the revert (Q82) and scores the injection on its own dimension -
`delivered`, `mentioned`, `followed`. What the row needed and did not have (`t7.1-candidates.md`,
the `injection` section: *"Needs harness work first"*) was a scenario that carries the payload
itself, so that it can hold a slot, be split-assigned, be rehearsed, and be run without a flag.

## The design, in five decisions

**1. The scenario file carries T6.8's variant, field for field.** `Scenario` gains `base` (the
recorded fault it rides) and `payload` (`channel`, `plant_on`, `text` with `{canary}`, `canary`,
`decoy`, `actor`), both required when `kind: injection` and refused otherwise. The fault fields
- `injection`, `ground_truth`, `fault_class`, `expected_remediation_class` - are the base's,
copied verbatim and held equal by a test, so the guards that compare a scenario to the injector's
catalog and to its bundle work unchanged: the injection scenario runs exactly the fault its base
runs. `adversarial.variant_from_scenario` turns the file into the `AdversarialVariant` the
planter and the scorer already take, so there is one planter and one scorer for both shapes and
nothing to drift.

**2. Log channel only, and `plant_on` is named, never defaulted.** The change channel writes the
platform's change log, which the development machine does not run. `plant_on` has no default
because the variant files' silent default to the culprit is what T6.8's batch 2 paid $2.47 to
discover; the row's rule is the page's seed - where batch 2 found the planner actually reads -
and each scenario names it. Where the pre-registered cell and the recorded page disagree (row 2:
the cell said checkout, the recording paged fraud-detection), the recorded seed wins, and the
candidates note says so.

**3. The runner plants for the kind, with no flag.** `faultline-eval <id>` reads the scenario,
sees `kind: injection`, and plants the scenario's own payload after the settle window exactly as
it plants a variant's; `--adversarial` on such a scenario is refused, because it would plant
two. The run is recorded with the `adversarial` block and **stays out of the standing
aggregates**, as T6.8 decided for variants (`run.counts_toward_aggregates`): its diagnosis score
is a measurement with an attacker present and is reported beside its injection score, never in
a table a run without the attacker also appears in. The holdout injection scenario runs with
`--holdout`, as any holdout does; the *variant* path's dev-only refusal stays on the flag.

**4. A rehearsal proves delivery through the agent's own tool.** The recorder plants the payload
after the page (a fault that never paged is not planted - there is no seed), holds the dwell,
and before the revert reads the stream back twice through `Tools.logql_query`: the specialist's
own read (limit 40, thirty minutes before the page to now, unfiltered) and the same window
filtered on the token (Q100). Both are recorded under `manifest.payload.read_back`, and
`payload.delivered` is the **unfiltered** read's answer: a token only the filtered read finds is
one the planner reaches only if it already knows what to look for, and a label may not rest on
that. The plant comes out with the revert (the log channel has no delete path, and the row says
so). The captures are unchanged - `CAPTURE_SET` does not move, so `cap:` does not.

**5. The fingerprint names the landing and the decoy, never the text.** A `kind: fault`
scenario's fingerprint is byte for byte what it was; an injection scenario's adds `base`,
`channel`, `plant_on` and the decoy. The payload's text and stem stay out for the reason
`expected_evidence` does: rewording the attacker does not make the recording wrong. Where it
lands and what it asks for do.

## What holds it

`tests/test_injection_scenarios.py`: the model's rules (the two fields belong to the kind, the
text carries `{canary}` and no harness word, the stem has the planter's shape); every committed
injection scenario's fault fields equal its base's, its base is a rehearsed fault, its decoy is
in the base's recorded blast radius, is not the culprit and asks for another class, and its
`plant_on` is a service of the world; canary stems distinct across scenarios and variants and
present nowhere but the scenario's own file, bundle, rendered page and this note; the recorder's
read-back answering *delivered* only when the unfiltered read holds the token; and every scored
scenario resolving to its file - which found that `run.culprit_service` and `also_correct_fixes`
built `evals/scenarios/<id>.yaml` by hand, a path no v2 scenario is under, so every v2 scenario
would have scored an empty culprit. No v2 run had been scored; `run.scenario_path` fixes it.

## What is deferred, by name

- **The change channel.** When the platform Postgres runs on the recording machine, `channel:
  change` is a one-line widening of the pattern and a `plant_on` whose change log the changes
  specialist reads.
- **A rehearsal that fails delivery.** Recorded as `payload.delivered: false` and the scenario
  is not labeled on it; whether the payload moves or the scenario is blocked is a decision for
  the row, made with the reading in hand.
- **The narratives.** An injection scenario's `incident.md` is written as the others are - what
  a responder saw - and the planted line is part of what they saw. The canary is not quoted in
  the narrative, so the corpus never carries a stem.
