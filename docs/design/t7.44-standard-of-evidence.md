# T7.44 — what standard of evidence does the benchmark reward?

A question about the scoring rules. **No rule is changed by this task**, and §6 says why that is not
a deferral.

## 1. What the rules actually specify — an answer key, plus a judged mechanism, and no standard of inference

**The scorer scores conclusions.** `score_label` compares returned class against truth class (with
`also_correct` where a second fix is measured); `score_triage` compares a predicted service set
against `alerts_over_window`. **Nothing in it looks at how a conclusion was reached.**

**The judge does assess mechanism**, and this is the part the premise of this task understated.
ADR-0022 §1.3 asks three structured questions, the first being:

> *"Root-cause agreement — does the verdict's root cause name the same mechanism the recorded
> `incident.md` names? Three levels: same mechanism, adjacent, different."*

plus dead-ends closed and **traps**: *"each recorded narrative names at least one confident wrong
answer available from the evidence. Did the agent take it?"*

**But none of that assesses warrant.** The judge asks whether the *named* mechanism matches and
whether a known trap was avoided. It does not ask whether the agent was entitled to name it. A
verdict reaching the right mechanism by temporal proximity and a verdict reaching it by traced
causation both score `same_mechanism`, because the question is what was named.

> **So: the benchmark scores conclusions, and judges the mechanism named in them. It specifies no
> standard of inference.** Whether a correct answer was reached well or by proximity is not
> assessed by any component. **Every claim this project makes about reasoning quality is our
> inference from reading narratives, not a measurement.**

### A correction to the premise, and it matters

**T7.41's two runs were never judged.** The sweep ended on an exhausted credit balance and judging
is a model call, so those runs were scored on **class labels alone** — the narrowest reading
available. The one mechanism-level check the benchmark has **did not run on them**.

**And it would not have separated them anyway.** Run 3 named the endpoint change; the recorded
narrative names the endpoint change; that is `same_mechanism`. Run 1 produced no root cause to
compare. **The judge would have rewarded run 3's proximity reasoning exactly as the scorer did**,
because it grades the named mechanism and not the warrant for naming it.

## 2. Two specific checks

### Abstention is scored consistently, and the incentive is intended and stated

ADR-0022 marks it as a decision with its alternatives named:

> *"`unknown` verdicts are excluded from the accuracy numerator and denominator and reported as a
> coverage figure. Rejected alternative: counting `unknown` as wrong, which collapses abstention and
> error. Also rejected: dropping them silently, which would let a system score 100% by answering
> once. **Coverage and accuracy are always reported together and neither is ever quoted alone.**"*

**The incentive is intended.** The stated purpose is that a system saying "I do not know" must be
distinguishable from one guessing badly.

**The guard against gaming it is disclosure, not scoring**, and that is worth saying plainly. An
agent that abstains selectively on hard cases keeps accuracy high and drops coverage; **no single
figure penalises that**, and the protection is that both numbers are always published so a reader
can see it. That is a deliberate trade — a scoring penalty for abstention would reintroduce exactly
the collapse the ADR rejected — but it is a trade, not an absence of a problem.

### The answer key encodes a mechanism, and nothing reads it

`GroundTruth` carries `root_cause: str` — a prose paragraph in every scenario — alongside
`category: FaultClass`.

**Nothing consults `root_cause`.** Across `src/` and `tests/`, the only reference to a scenario's
ground truth beyond the schema is a test asserting `ground_truth.category is scenario.fault_class`.
The judge compares against **`incident.md`**, the recorded narrative, not against the answer key's
prose. **The mechanism in the answer key is inert**, and it is fingerprinted, so it cannot be edited
without invalidating bundles despite being unused.

**This is the concrete form of the gap.** The benchmark cannot distinguish a right answer reached
well from one reached by proximity — and the field that describes the mechanism authoritatively is
sitting unread in every scenario file.

## 3. The substantive question, argued both directions

### For the looser standard — a wrong value is itself the mechanism

**Real incident response works this way.** A config change minutes before an incident, on a service
that is otherwise healthy, is a diagnosis a competent on-call engineer makes and acts on. Waiting for
a traced causal path is how incidents get longer, not shorter.

**Demanding a traced path would make most real diagnoses impossible.** Tracing *endpoint repointed →
spans stop → spanmetrics stop → `calls_total` drains → `ServiceNoTraffic`* requires knowing the
telemetry pipeline's internals. That knowledge is not in the evidence and no tool exposes it.

**And decisively: this catalog contains items whose only route to the answer is the change record.**
`redis-cart-dependency-latency`'s own CATALOG entry says `change_history` is *"the only class in the
bundle that names `redis-cart` at all"*. `shipping-quote-misconfig` is recorded as a scenario where
*"`change_history` was the only class that named it"*. **If a change record plus proximity were an
illegitimate warrant, those items would be unanswerable by construction** — and T7.40 already decided
the evidence that would trace them will never be captured.

### For the stricter standard — proximity is the inference this project keeps getting wrong

**This project has caught itself reasoning from proximity and been wrong repeatedly**, and recorded
each: T7.13's degenerate-histogram reading falsified by T7.14; T7.26's kafka retention item falsified
by re-measurement at T7.27; T7.39's audit asserting a property of the injector from a document that
asserted it first. **The discipline that produced those corrections is exactly the discipline run 1
applied.**

**A benchmark that rewards what its own project warns against is incoherent** — and here the
incoherence has a name: run 1's reasoning was better by the project's own standards and scored
worse.

### Resolution, not by preference

**The catalog decides it.** The benchmark's items are built so that a change record is often the only
available warrant; several are answerable by nothing else. **A standard requiring a traced mechanism
would make the benchmark's own scenarios unanswerable**, which is not a standard, it is a
contradiction.

**So the standard the benchmark applies is coherent with what it asks:** an exonerated service, a
sole in-window change, and temporal proximity constitute sufficient warrant, because in this world
they are frequently the only warrant obtainable.

**And the tension with project practice dissolves once the two situations are separated.** The
project reasons strictly about its *own* claims because it can run a controlled test — inject twice,
re-measure, falsify. The agent has one incident window and four tools and cannot re-run anything.
**Requiring of a one-shot investigator the standard appropriate to a repeatable experiment is the
error, not the leniency.** That asymmetry is defensible and stating it is what resolves the apparent
incoherence.

## 4. Does this mean the benchmark measures something narrower than claimed?

**Narrower than the project has sometimes said in prose, but not narrower than its published
figures claim.** The figures are label-level and named as such — coverage, fault class, class of
fix, triage recall and precision, judged `same_mechanism` — and README carries no claim that
reasoning quality is measured. Its strongest claim, *"every claim cites verifiable evidence"*, is
about citation, which **is** enforced: ADR-0022 §1.2 validates every `result_id` against
`trajectory_tool_calls`.

**So no correction to README or RESULTS is required by this task**, and inventing one would be
worse than none. **What is required is that the distinction stops being assumed in prose**: writeups
in this project have described runs as reasoning well or badly, and that reading is ours. The rule
this yields is in §6.

## 5. What is not changed, and the explicit statement the standing rule requires

**No scoring rule is changed by this task, and none should be changed on this evidence.**

> **This conclusion is not motivated by the fact that a different standard would have scored
> T7.41's run 1 differently, and must not be adopted or re-opened on that basis.** T7.43 was an
> n = 1 pair. The reasoning above rests on the structure of the catalog — that several items are
> answerable only through a change record — which is true independently of any run.

## 6. What would close the gap, queued and not adopted

**The unused `GroundTruth.root_cause` is where a warrant check would go if one were ever wanted.**
The key already states the mechanism authoritatively; a scorer or judge could compare a verdict's
*stated causal path* against it, rather than only the mechanism it names.

**It is not proposed for adoption**, for three reasons: it would change what the benchmark measures
on the strength of one pair of runs; it would require re-scoring every stored verdict to stay
comparable; and it is not obvious that a one-shot investigator *should* be graded on warrant when the
evidence to establish warrant is often absent by design (T7.40).

**What would justify revisiting it:** a measurement showing correct answers split by warrant — that
agents reach right conclusions by proximity often enough for the distinction to change a published
figure. **T7.43 named that test and priced it at ~$5.5. It has not been run.**

**The rule this task does adopt, because it costs nothing and changes no scoring:** a writeup may
report what a verdict *named* and what it *cited*, both of which are recorded. **It may not describe
a run as having reasoned well or badly without saying that this is a reading of the narrative and
not a scored quantity.**
