# T7.50 — does the action plane survive T7.18?

Design analysis. **Nothing built, and ADR-0028 is not amended** — the proposed change is queued
instead, per the brief.

## 1. The premise needs correcting before the question can be answered

**ADR-0028 does not predate T7.18. It *is* T7.18** — `Date: 2026-08-29`, `Task: T7.18`. The design
and the finding are the same task's output, so "written before the finding that most threatens it"
does not apply.

**And it does not merely mention the axis.** §5 is titled *"Contamination — a third axis, and it is
the sharpest one"*, gives it a full section, and states the mechanism in the same terms the brief
does:

> *"A loop that proposes, executes, observes and re-proposes converts diagnosis into **search** — and
> it would score well, because the fault is real and a small number of candidate fixes covers most
> of the catalog. That is not a better investigator; it is a worse one with a working oracle."*

It then takes a marked decision — *"one proposal per incident, executed at most once, and no
observation of the result re-enters agent context"* — states that a propose→observe→re-propose
variant *"needs its own pre-registration and its own scoring, because it is measuring a different
capability and would make every prior number incomparable"*, and assigns the axis a home in
ADR-0008 when the role is built.

**So the answer to the first question is: yes, and more thoroughly than the brief assumed.**

**§2 closes the axis structurally rather than by policy.** The proposer **does not act**: a human
stands between proposal and execution, approval is per-proposal, there is no autonomous path, and
a confidence threshold is explicitly rejected because *"it makes the model's own calibration the
safety boundary"*. **An oracle requires a loop; the design has no loop to close.**

## 2. The enforcement gap — the one thing §5 leaves implicit

**§5's control is stated as withholding: "the execution outcome goes to the trajectory and the
scorer, never back to the model." That is not what actually closes the channel, and the difference
matters for whoever builds this.**

**Withholding the executor's return value is insufficient on its own.** If a change is applied while
the agent can still issue a query, the agent's *existing read tools* observe the changed world —
`promql_query` sees the error rate fall, `logql_query` sees the restarts stop. **The world is the
side channel, not the return value.** An implementer reading §5 as "just don't feed the result back"
would build something unsound and would pass the letter of the decision.

**What actually closes it in the designed system is sequencing:** the proposal is terminal, the
agent's turn ends, a human approves, and the executor acts afterwards. There is no subsequent read
because there is no subsequent agent.

**This is worth writing into the ADR** because the two controls come apart precisely in the variant
§5 anticipates. It is the clarification queued below.

**One design element already does more than the ADR claims for it.** The proposal carries
`expected_effect` — *"what should be observed afterwards, as a predicate over telemetry the four
tools can already reach"* — and `confirm_within`. **That is a pre-registration**, imposed on the
agent, of exactly the kind this project imposes on itself. A committed predicate turns a subsequent
observation into a **test of a prediction** rather than a search signal: search requires acting and
*then* deciding what the result meant. It does not make execute-and-observe safe, but it is the
mechanism that would make a repair benchmark scoreable, and §4 should say so.

## 3. What the benchmark would measure if action were permitted

**Precisely this: the ability to find a working fix by trial within a budget.** Not the ability to
name a cause from evidence.

**Three things make the substitution near-total on *this* catalog**, which is what turns a
philosophical worry into a measurement failure:

1. **The candidate set is tiny.** ADR-0020 defines **five** remediation classes. Trying them
   exhaustively is a five-step search.
2. **The scorer scores the remediation class.** An agent that tries `restart` and observes recovery
   has produced the correct label **by construction**, with zero diagnostic content behind it.
3. **Some scenarios have more than one working fix** — ADR-0027 and T7.17 measured two for
   `dependency_latency`. Trial succeeds even more easily than the class count suggests.

**Is it still worth measuring? Yes — and it is a different benchmark.** "Can an agent restore
service within k attempts" is a real and arguably more operationally valuable capability than "can
it name the cause". **The danger is not that it is worthless; it is that it would carry the same
name and be compared against figures measuring something else.** Every number in RESULTS was
produced by an agent that could not try anything, and none of them would remain comparable.

## 4. The four designs, against what this harness can actually enforce

The harness's real capabilities: the injector knows what it injected; the scorer sees remediation
class; the world lock exists; revert is a recorded operation; **`trajectory_tool_calls` records
every call, so counting actions is trivial**; and the runtime is in-house (ADR-0003), so what enters
context is controllable.

| design | enforceable here? | verdict |
|---|---|---|
| **A. Score the diagnosis before any action is permitted** | **Yes, trivially — this is already what happens.** The verdict is scored at synthesis, before any proposer exists | **Sound, and it is the current design.** Costs nothing because it is already true |
| **B. Permit one action; treat further ones as abstention** | Counting is trivial. But **the premise is wrong**: one action is one bit of oracle, and one bit distinguishes two hypotheses. On a five-class space with a real fault, that is a large fraction of the remaining uncertainty. And "abstention" is a property of a *verdict*, not of an action count — the mapping is a category error | **Rejected.** It does not preserve the measurement, it rations the search |
| **C. Separate a diagnosis benchmark from a repair benchmark, scored apart** | **Yes.** Diagnosis scoring is untouched and its figures stay comparable. Repair is scoreable from what the proposal already carries: was `expected_effect` satisfied within `confirm_within` | **The right shape**, and §5 already implies it by requiring a separate pre-registration |
| **D. Permit action; record attempts beside accuracy as coverage sits beside it** | Counting: yes. But coverage works because **abstention is visible in the verdict and changes nothing about what accuracy means**. Attempts change what accuracy means: 100% at three attempts and 100% at zero are not the same measurement, so the pair would have to be quoted jointly *and never compared to any historical figure* | **Honest but expensive.** It is the correct form of "permit action" and it retires the comparability of every existing number |

**A and C are the same answer seen from two ends**: score diagnosis where it is already scored, and
if repair is ever built, build it as its own benchmark with its own pre-registration. **Neither
requires enforcement this harness cannot perform.** B and D both do preserve *something*, but B
preserves the wrong thing and D pays for it with the entire published record.

## 5. Should T8 be built as specified?

**Yes as specified, and the specification is the reason.** ADR-0028 specifies a proposer that does
not act, behind a human, with no autonomous path — and that is precisely the version the oracle
argument does not defeat. **The thing to resist is not T8; it is the natural next step after it**,
which §5 already fences off and which this analysis strengthens the fence around.

**What should not be built is the loop** — propose, execute, observe, re-propose — under the current
scoring, under the current name, or compared to the current figures. That is not a refinement of
this benchmark; it is a different one.

**And the record should carry the reason so it is not rediscovered.** The queued amendment below is
the mechanism.

## 6. The proposed amendment, queued rather than made

**ADR-0028 §5 should state that the oracle control is *sequencing*, not *withholding*** — that the
agent's last read must precede any execution, and that withholding the executor's return value is
insufficient because the agent's own read tools observe the changed world. **§4 should record that
`expected_effect` and `confirm_within` are what would make a repair benchmark scoreable**, so the
separation in §5 has a mechanism attached rather than only a prohibition.

**Not made here**, because an ADR rewrite is a decision and this analysis is one task's reading.
Queued in [`docs/QUEUE.md`](../QUEUE.md) as **Q7**, with its trigger: **the first task that proposes
to build any part of the action plane.** Until then nothing depends on it, because the proposer is
unbuilt — `roles.py` carries planner, scribe, specialist and synthesizer, and no proposer.
